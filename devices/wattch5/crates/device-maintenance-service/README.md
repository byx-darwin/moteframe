# Maintenance wire services

Independent `no_std`, no-heap, unsafe-forbidden adapters for the frozen `device-maintenance` engines and a separate commercial persistent job service. There is no hardware, storage, authentication, clock, FIFO or successful fallback backend in this crate. Offline fixtures prove wire and actor behavior, not physical hardware or power-loss persistence. Board/product integration and its acceptance remain outstanding.

All features are opt-in; default selects no handler. `module_compiled` reports compile selection only. Register a module as actually available only after its real mandatory ports, current product policy and negotiated carriers are supplied.

| Feature | Handler / actor | Module version | Implemented wire |
| --- | --- | --- | --- |
| `raw-data` | `RawActor`, `RawHandler` | 70 = 1.2 | LIST 01, CHANNEL 02, CONFIG 03, START 04, STOP 05, STATUS 06, BATCH E80 |
| `self-test` | `SelfTestHandler` | 71 = 1.1 | LIST 01, RUN 02, RESULT 03, CANCEL 04, EXTERNAL_RESULT 05 |
| `engineering` | `PersistentMaintenanceHandler` | 72 = 1.0 | C40/C41; explicitly selected optional C42 output |
| `factory-config` | `PersistentMaintenanceHandler` | 73 = 1.0 | C40/C41; explicitly selected optional C42 output |
| `device-jobs` | `DeviceJobsOwner`, `DeviceJobsHandler` | 02 = 1.0 | C40/C41, DATA_CLEAR 0001, FACTORY_RESET 0002 |

Module versions are registration versions; schema1 inside versioned parameter/output bodies is independent. Only raw BATCH has its specified CRC and exact 46+N body overhead. Selftest, persistent operations and commercial device jobs have no invented CRC. Handlers check complete request length and capacity before accepting effects and implement `device_services::ServiceHandler` for the connection's real `Session`/`ControlConnection` admission/cache lifecycle.

## Raw DATA integration

Construct `CleanupTrace`, then `RawPortObserver::new(&mut actual_raw_port, &trace)`, and pass that observed real port to `RawActor::new`. The other inputs remain real controlled manifest/channels, live `Authority`, trusted `Clock`, the connection's shared `DataLane`, a mandatory `DataSessionCloser`, and actual HELLO-negotiated `data_max` (128..512). The metadata carrier is separately checked. A station identity must be nonzero and remain current. `RawHandler` borrows this same actor; do not create separate lane owners for Core07/history/raw.

The core resource bridge can use `grant_authorized()` to ask actual Capture authorization without requiring a current stream, `validate_grant(stream,cumulative)` for a pure preflight, `grant(stream,cumulative)` for the actual cumulative grant, and `grant_replay_valid(stream,accepted)` for cached Core07 context freshness. The latter verifies the exact still-held lease and becomes false after normal STOP/final drain releases it. An informational CoreAccess authorization does not grant Capture.

START actually accepts/starts the frozen capture engine. Its exact response must be admitted through `ServiceHandler::response_admitted` before grants or BATCH can progress. `start_batch(queue,frame_max)` requires the shared `device_connection::FirstFragmentQueue`: its `FnOnce` fill closure runs only while a real first FIFO slot is held, calls `begin_batch`, and encodes/adopts the first fragment in that same serialized actor boundary. `NoSlot` calls no fill, allocates no message ID and consumes no sample. A readiness bool is insufficient. `Admitted` means actual admission, not a promise to enqueue later.

Transport/commit uncertainty ends the same whole DATA owner via `DataSessionCloser`, mutes producers and attempts physical disconnect. The closer must call the real shared connection lifecycle, including history, rather than merely stopping raw. It must not reenter this actor while it is borrowed. A failed cleanup remains an error on repeated closes. The mandatory observer records every real stop error outside the frozen engine, including an engine-internal revoke/close that discards its stop return. Every actor/control entry observes that same nonrecyclable trace. An already-closed engine cannot turn a known failed stop into successful cleanup, and a failed trace cannot construct a new actor view.

After first admission, call `next_frame` to prepare an immutable continuation; retries return the same bytes. Call `confirm_frame(receipt)` only after that exact fragment is admitted to the same actual FIFO. The opaque receipt binds stream/message/offset/end. Only the final confirmation calls `finish_batch` and counts samples emitted. It proves FIFO admission, not peer persistence. Keep negotiated `frame_max` fixed for the flight. Idle and absolute deadlines use trusted admission time; failure closes/mutes the shared owner.

Call `poll` while active and while STOP drains. STOP is genuinely deferred through `response_ready` while the in-flight BATCH drains; an unknown nonzero stream instead reaches dispatch and returns the normal NotFound wire response without faulting the connection; no private Pending status is placed on wire. Its final response has actual produced/emitted/dropped counts and the admitted barrier ID. A no-slot unstarted sample is dropped on STOP. Scope loss, CCCD disable, disconnect, clock failure or deadline loss requires the connection cleanup path, not a normal STOP response.

## Controlled selftest

`SelfTestHandler::new` takes the exact real `TestSpec` manifest, a mandatory `SelfTestPortObserver` over the real `TestPort` and its own `CleanupTrace`, live station/authority, trusted clock, actual static `TestListFlags`, and independent `EvidenceVerifier`. LIST caches only the manifest/backend intersection; method comes from the same engine spec. No criteria, evidence signature or PASS result is fabricated. Ordinary selftests must exclude calibration writes, user-data erasure and factory reset; those actions belong to durable C40 jobs.

RUN validates actual scope, any DangerousSelfTest scope, timeout/options and criterion, then calls the frozen engine's acceptance/start path before returning its real connection-local job ID. Physical start can therefore precede response admission. The handler gates RESULT until actual RUN response admission; there is no claim that all physical actions are response-first or that RUN has cross-reconnect exactly-once semantics. Drive `poll` from the actual application executor. Terminal RESULT is exact 29+8N data bytes (plus the 4-byte response status); its origin/station/evidence and typed metric scale/unit are preserved. Manual verdicts require independent verified evidence tied to the same job/test/station/criterion. CANCEL of an old terminal job cannot clear a newer dangerous-job guard. Call connection cleanup on CCCD disable/disconnect; physical cleanup failure remains explicit, including timeout cleanup that already closed the underlying engine. All engine calls (RUN, RESULT, CANCEL, EXTERNAL_RESULT, periodic poll and cached validation) pass one cleanup fence; a failed actual cancel closes the App actor and stays visible through repeated teardown. This also covers a start failure whose attempted physical cleanup fails before RUN can return a job.

## Persistent maintenance72/73

`PersistentMaintenanceHandler` takes actual `StorageBackend`, the same immutable `OperationSchema` reference also given to `PersistentEngine`, live station/authority, clock, and `PersistentMaintenanceExecutor`. The wire checks frozen typed schema1 parameter shapes/ranges for every72/73 operation before engine acceptance. The same schema's actual policy validates additional product restrictions and DangerousMaintenance; missing initial D returns FF04 before calling the engine. The engine validates that policy again at its atomic storage boundary. A second policy copy or a default non-dangerous policy is forbidden.

C40 returns the actual durable job ID; C41 returns the exact persistent state/result/reason5B, not selftest state codes. Optional C42 preserves actual operation/schema/output bytes and the frozen engine's original-policy output validation. Set its constructor selection only from the trusted product manifest. `PersistentMaintenanceExecutor` must share the engine's actual ledger, bind the original policy revision/whole identity, recheck live authority and binding, and atomically claim Accepted→Running in `response_admitted`. Only that hook may begin physical work; retries of Running/terminal jobs must never repeat it. The handler captures pending/cache dangerous policy so revocation also fences deferred/cached responses. Persisted jobs outlive a BLE view; disconnect closes that view without falsely canceling or completing durable physical work.

`NamedOutput::decode` additionally checks all17 named-operation schema1 output bodies beneath C42: sensor/touch status, resource CRC and extent, interrupt count, signed ADC samples/comparison with unit and scale, calibration revision, gesture samples and parameters, ageing result, actual off duration, empty EXIT_TEST, and actual product/serial/subtype/enable readbacks. Decoding rejects trailing bytes, invalid serial digits/length and non-boolean enable values; its typed borrowed view allocates nothing and redacts payloads in Debug. C42 applies this structural check after the original product policy, clears rejected output, and returns Storage rather than forwarding malformed backend bytes. Real manifests must still validate identifiers, ranges, units, sample limits and criteria. Structural decoding does not establish a physical PASS or implement the executor. The API is excluded when only commercial `device-jobs` is selected.

## Independent commercial02 jobs

`device-jobs` does not select `device-maintenance` or any70–73 feature. Commercial products must register only the desired02 adapter and keep all engineering features disabled. Both operations take exactly the v06 schema1 body `[01,00]` inside C40's operation-ID/operation/parameter-length envelope.

Create one product-global `DeviceJobsOwner` with a real `DeviceJobLedger` and `DeviceJobExecutor`; connection-local handlers borrow it. The ledger namespace is fixed module02. If sharing a physical store with another namespace, the store must retain that namespace as part of its binding. Atomically bind the complete `operation_id`, operation, all parameter bytes, real principal and immutable policy revision; persist a nonreusing job before C40 acceptance. Claim/query never execute hardware. Actual guarantees must include atomic/durable identity, durable terminal state, recovery completed for this boot, reset-preserved ledger and at least32 retained unconfirmed terminal records plus dedup tombstones. `Unavailable` rejects construction/use. These are mandatory backend contracts, not evidence of a flash implementation in this crate.

The handler prechecks real operation+D permission before claim, and caches the principal/job binding. A full real ledger returns exact wire LimitExceeded0007 with no claim/execution. Short caller output buffers remain local Capacity and are checked before the ledger. At actual response admission the ledger atomically changes Accepted→Running with live scope/full binding, then the executor receives both actual record and live `DeviceJobAccess` for a final physical-commit check. AlreadyStarted/Running/terminal replay does not execute. An uncertain execution or durable commit returns an explicit error and preserves identity; it never becomes a fabricated success or triggers an automatic retry with a new ID. Reboot recovery must persist Interrupted for unresolved old jobs before opening wire service; do not replay their physical actions.

Actual DATA_CLEAR must stop acquisition, atomically rotate the dataset and clear the documented owner data domains. FACTORY_RESET additionally restores trusted defaults/binding. Device identity, calibration and the isolated durable job ledger survive. No partial work is a successful terminal result. The trusted background `owner.poll(id)` drives only actual Running work after a BLE disconnect/unbind, validates the exact persisted identity, and persists actual terminal outcome atomically. It is not an unscoped wire query and may not initiate new privileged work. `terminal_persisted` permits a real reset/reboot only after the final actual terminal record was stored; unknown outcomes remain explicit. C41 still needs actual current read scope and per-record permission.

## Independent review fixes and constructor migration

The four confirmed findings from the separate review were reproduced as permanent tests before the changes (`red-review-regressions.log`): Raw cleanup swallowed after an engine-internal revoke, SelfTest timeout cleanup through RESULT/other entry points, unknown STOP readiness, and commercial ledger capacity. The original review directory and frozen engines remain untouched. Further RED evidence in `red-review-all-entry-rebind.log` covers direct STOP dispatch and refusal to reopen a failed real test port. `green-review-all.log` records all fixed regressions.

`RawActor::new` now requires `&mut RawPortObserver` and `SelfTestHandler::new` requires `&mut SelfTestPortObserver`, replacing the former bare trait-object inputs. Keep the actual port, then its trace, then its observer alive for the actor lifetime. Observer constructors return Busy when a trace was already bound to any port; one trace cannot mix Raw/Test producers or be recycled. The observers exclusively forward actual backend methods, without simulation, heap or unsafe. Both actor constructors reject retained failed cleanup evidence.

A trace has no clear/reset API. Ending the App actor or obtaining an idempotent closed-engine result never proves physical recovery. Any subsequent product recovery must establish actual hardware truth outside this closed view before making a new real binding. The existing shared FIFO reservation, final-fragment accounting, commercial dependency isolation, durable execution claim and 71 RUN acceptance timing are retained.
