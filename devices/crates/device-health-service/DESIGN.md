# Health service design and execution plan

Implement the coordinator's approved health wire integration specification within this independent workspace. One boot-scoped SharedHealthOwner owns the existing JobManager and a real multiplexing Backend. One HealthHandler handles all selected module entries for a physical connection; all modules therefore share IDs/resource arbitration. Checked RefCell borrowing reports Busy. Connection identities are nonzero monotonic and cannot reopen an old handler. Device jobs can be maintained through the same shared owner, never a second manager.

Injected ports supply live resource/job authorization, monotonic clock, real product declarations/provenance/start ownership, and actual atomic latest storage. START is accepted in dispatch; result/end APIs remain gated until response_admitted. STOP's end is also response-first. Events are peek/confirm, retained byte-identically under backpressure and cleared on cleanup. Each actual body is decoded by device-health and checked against ProductDeclaration. LATEST response and result events enforce the actual carrier with the exact event body (no additional CRC). Cached LATEST validates its storage generation and auth before release. Five-zone route/event is registered only when an explicit real zone port is supplied; codecs validate the 31B/35B schema.

TDD sequence: (1) write compiling behavioral tests against the API shell and observe assertion RED; (2) shared owner/connection authorization and START admission; (3) STOP/QUERY/LATEST/results/end and carrier/provenance; (4) zone port/codec, exact bytes and feature selection; (5) Host default/all/single features, ARM all/single and strict lint matrix. High-risk tests cover shared PPG conflict across modules; unchanged FIFO retry; stop response-before-END; per-job revocation; latest generation and carrier overflow; failed cleanup retains resources; no backend/no result fake success. No hardware/Git operation and no edits outside this crate.
