# Bounded connection orchestration

The board executor owns one physical connection, one `SharedControlChannel`, and real service actors. It constructs `(control, event_channel)` with `ControlConnection::with_events(config, &owner)`, then passes the unique token and its permanently bound source to `EventPump::new(event_channel, source)`. Control-only `ControlConnection::new` cannot issue an event token. The owner has no reset; use a fresh owner for a new physical connection.

Enable control notifications, receive actual HELLO, and drain its response through real FIFO admission. The pump reads that same connection's negotiated limits and immutable catalogue. `flush(now_ms, plane, queue)` has no caller-supplied readiness flag or independent limit snapshot. It neither peeks nor prepares an event before HELLO is active, and it cannot start one while HELLO's response is pending.

An ordinary control EVENT owns logical control TX from its actual first-fragment admission through whole-event confirmation. A new REQ may still be received completely into the bounded receive buffer; `Receive::Deferred` retains it without executing the business handler. Call `poll_pending(actual_now, handler)` after draining event fragments. This is local scheduling, with no wire Pending response or client retry. Partial REQ, queued RESP and handler prerequisites all prevent new events. An already-started DATA message uses the independent shared data lane and can drain while a real CANCEL/CLOSE waits for its barrier.

There is exactly one in-flight request. If that request/response slot is already occupied, `receive` returns `Busy` without consuming the next write. A transport must apply real ingress backpressure or retain the complete GATT value for a later retry. It must never acknowledge and silently discard that write. A successfully admitted incoming value is not proof that a business operation or peer persistence has completed.

`FirstFragmentQueue` reserves the actual first notification slot before invoking source preparation. `NoSlot` cannot consume credit or a DATA ID. A benign source `NotReady` rolls back the control logical claim. Publication uncertainty closes the connection; it cannot be treated as a full FIFO. The board adapter must serialize fresh authorization, generation checks and actual queue publication.

Call `control.tick(actual_now, handler)` on the foreground executor even without incoming writes. It checks deadlines and fans actual monotonic time through `ServiceHandler::advance` before processing new requests. `HandlerTable` attempts every service even if one advance fails. Stateless handlers use the true default noop; a history handler advances its own lease clock. The same actor must back resource providers and event handles.

Either half's close/fault permanently mutes the shared context. Explicitly close both halves to execute all actual backend cleanup and inspect both results. Failed cleanup remains latched; another explicit `close` retries it and reports its real result. Drop mutes the context and clears owned bytes but cannot call an externally borrowed business handler or claim backend cleanup succeeded. The counterpart's next operation reports `Closed` and attempts its own cleanup.

All tests use offline queue/backend fixtures. Host tests, target builds and protocol reassembly prove software contracts only; no BLE adapter, persistent store or real hardware effect is supplied here.
