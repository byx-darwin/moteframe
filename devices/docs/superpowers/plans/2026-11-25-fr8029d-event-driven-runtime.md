# 裸机与 FreeRTOS 共用事件驱动运行时里程碑

目标是在设备工程内复用 BLE、UI、传感器和存储逻辑，由设备固件在构建时选择裸机或 FreeRTOS。两种构建共用板级事件来源和有界工作步骤。裸机入口在空闲时等待中断，FreeRTOS 入口用任务通知等待。MoteFrame 的公开接口保持兼容。

FR8029D 是首个 BLE 实机目标。现有裸机和 FreeRTOS GATT 样例作为对照。Mac CoreBluetooth 负责广播发现、连接、订阅、带响应写入和对照通知，J-Link 负责板上计数和栈水位。早期集成从 SRAM 运行并在测试结束后复位回原厂固件。Flash 执行版的镜像和 SRAM 预留按 ELF 统计，冷启动验收单独记录。

## 1. Mac BLE 验收基线

- [ ] 在 `scripts/ble_connect.swift` 增加 FR8029D 裸机和 FreeRTOS 探针选择，保留原 `RUST-LINK` 入口与其协议。
- [ ] Mac 按探针名和 GATT UUID 确认识别，订阅成功后发送同一组 8 字节测试数据。只有写入确认和同一特征值的回显都通过才判成功。输出可区分扫描、连接、服务发现、订阅、写入和回显故障的日志。
- [ ] 从 SRAM 分别运行 `FR29-GAT2` 和 `FR29-RTOS`，记录 Mac、J-Link 和原厂恢复结果。手机历史记录保留为对照。

## 2. FR8029D 共用硬件唤醒

- [ ] 在 `firmware/fr8029d-bringup` 接入基带事件结束中断和硬件定时器。中断记录事件并唤醒执行端。事件处理和控制器状态继续由 BLE 所有者串行执行。
- [ ] 先验证连接窗口的最早截止时间、计时回绕、挂起标志与进入等待之间的竞态，并验证丢失完成中断后仍能到达原有超时路径。
- [ ] 为裸机构建接入中断等待，为 FreeRTOS 构建接入任务通知。实机分别记录唤醒次数、等待次数和连接窗口的最差余量。

## 3. BLE 事件驱动与 HCI 兼容

- [ ] 在 `crates/ble-controller` 增加外部事件唤醒的 HCI 路径。现有轮询调用仍通过回归测试。新增行为覆盖空闲不自唤醒、TX 有空间再唤醒、取消和重连过程清理旧等待者。
- [ ] 为 FR8029D Host 和射频后端提供可唤醒的最早截止时间。保持连接参数更新、广播恢复、CCCD 和 8 字节 Notify 行为可用。
- [ ] 裸机版和 FreeRTOS 版均完成 Mac 连接、订阅、写入、回显和断开后重连。用 J-Link 证明空闲时执行端实际进入等待。

## 4. 整机设备运行时接入

- [ ] 以 `crates/device-runtime` 的 `Runtime::step` 为共用执行入口，在设备层接入事件和最早期限，继续使用现有运行时的连接代次与资源所有权规则。
- [ ] 分别接入 UI 局部刷新、传感器就绪和有界 I²C 事务、存储请求与完成事件。驱动在等待期间释放执行机会，共享总线、队列满和存储提交失败各有可验证的行为。
- [ ] 在两种固件中运行同一套业务和故障回归。接入对应外设后，在刷屏、采样和存储并发时复测 BLE。只有实际装配的外设才记为板验通过。

## 5. 双构建交付

- [ ] 记录两种构建方式和 Mac 验收命令，核对公共调用方和历史固件构建组合。
- [ ] 用同一组业务工作量对比 Flash 镜像、静态 SRAM、栈预留、栈覆盖深度和 BLE 响应时间。区分实测和链接布局，记录原厂恢复结果。
