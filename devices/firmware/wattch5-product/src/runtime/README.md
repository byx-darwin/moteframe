# Callable Wattch 5 product runtime

Enable `runtime` to compose the accepted portable `device-runtime::Runtime` with the existing V2 UI and actual durable settings/time services. This is an allocation-free, unsafe-forbidden library entry. It does not initialize a board or replace the preserved offline self-check binary with a flashable image.

## Binding and startup

Strictly open the six caller-owned durable partitions with their existing owners: `ConfigStore`, `PropertyStore`, `DurableObjects`, `HistoryStore` or optional `paged::PagedHistoryStore` (including ACK), `TimeStore`, and `JobStore`. Corruption/open errors remain errors; no product adapter formats them. Explicit initialization remains the existing owners' responsibility. `initialize_blank_settings` offers only an explicit `KeepBlank` or caller-supplied complete defaults on a confirmed blank property owner. Time is initially unsynchronized until its actual authorized synchronization succeeds. The paged history selection requires caller-supplied, disjoint metadata/log views from one checked `PagedMedia` owner; its recovery adapter reloads the real log and ACK metadata and propagates failures. It does not grant a physical partition or activate history DATA.

`SelectedWarehouse` takes mutable references to those six existing owners, with family-specific sealed trait bounds preventing mislabelled positions. `boot_existing`/`recover_after_shutdown` call all six actual recovery methods independently and return a separate result for every family. A successful reload does not promise an initialized partition, a valid clock, available wire modules, or a selected algorithm. Close the runtime successfully, drop old connection actors and borrowed UI/factory views, then recover. Rebuild views and the runtime afterwards; never recover a store underneath a live stateful object/history/job actor. After destructive cleanup failure, resolve it through `Runtime::retry_cleanup` before proceeding.

The existing `heart-rate` and `sport` product features forward weak optional features to the shared configuration owner, so `runtime,wattch5-source` opens the real HR policy/zones schema. Runtime alone leaves shared configuration's selected schema empty. Neither selection supplies measurement algorithms or grants authority.

## Actual CONTROL entry

Construct `ProductFactory::new` with the same boot-owned settings/time owners used by the UI, actual `BleAuthority`, a stable truthful `Config` and a borrowed `Extensions` factory. `Config.session` is the first nonzero application session; each successful open consumes a checked increasing ID. It is informational, not an authentication token. Actual product identity, capability revision, capacities, dictionaries, access and transport subscription generation remain trusted integration inputs. Frame capacities are clamped to the smaller of the configured product ceiling and actual subscription capacity. DATA capacity must be zero.

`factory.runtime(budgets)` creates the actual foreground coordinator. Call `runtime.step(now_ms, &mut actual_transport, &mut product_ui, &mut actual_background)` repeatedly. The required transport is the accepted real `FirstFragmentQueue` scope/reservation/publication boundary; no production transport implementation or successful background default is supplied here. Call `shutdown` explicitly; Rust destruction does not establish fallible cleanup success.

Each CCCD enable obtains a fresh `ProductHandler`, durable time handler and optional extension actor. Ordinary properties are stateless temporary bridges into the same actual property owner; no per-request property session/cache is replaced. The owning protocol Session retains replay, readiness, authorization, admission and cleanup authority. Every current ServiceHandler hook is forwarded, and mutable composition uses the existing HandlerTable. Duplicate route ownership, unsupported features and a selected available module without an actual bound route fail before HELLO publication. Actor ownership is transferred to Runtime even when this validation fails, so fallible extension cleanup remains retained instead of disappearing on a constructor error.

`NoExtensions` means explicit unsupported optional business routing. Actual object/job/etc actors may be supplied through `Extensions::open` and retain all state across requests in that subscription. Their providers/owners remain external. History DATA/events are not integrated: CONTROL-only composition must not advertise features requiring those producers. Adding a recovery adapter never makes a business module available.

## Shared settings and UI

Use one `PropertyStore<CodecSchemas>` with the exact selected actual catalogue and product facts. `Settings::new` validates all dictionary values against that same owner. Its only durable appearance mappings are actual schema fields:

| V2 field | Module/key | Actual codec |
| --- | --- | --- |
| Clock format | 04.0003 | HourFormat(0=24h, 1=12h) |
| Implemented locale | 04.0007 | Text(actual Chinese/English identifiers) |
| Normal brightness | 04.000A | Brightness(one of five actual increasing levels) |

The caller provides the real five normal levels and two identifiers; no product defaults or invented wire keys are generated. Face/theme/text size obey explicit `RamFields::RamOnly` or `Unavailable`. RAM-only state does not survive UI reconstruction. BLE `PropertyAccess`/`TimeAccess` and local `UiAuthority` are separate inputs, checked at real reads/commits and response publication.

`ProductUi` consumes a fallible normalized `TouchSource`, fallible `ObservationSource`, fallible trusted `Calendar`, real initialized 128x128 `Display` and explicit `Actions`. NoActions rejects every external request. Unsupported measurement, clear/reset, timer, backlight preview and other external actions never become successful because a codec is compiled. The caller supplies each full snapshot field from actual observations, marking unsupported measurement/timer states unavailable and readings missing. The existing UI Snapshot has mandatory battery/activity/calendar fields without a missing variant; when those observations are absent, the source must return `Unavailable`. It must never fill them from Snapshot::default or demo data. TimeStore supplies the real UTC mapping; invalid/absent synchronization prevents rendering. Calendar conversion supplies real local date/time and validates through the existing snapshot contract.

Appearance events run on an outer staged Model copy. An actual durable commit and live local policy check must succeed before the staged model replaces confirmed state. A failed/uncertain commit leaves the confirmed UI unchanged, even when an uncertain write later proves durable; explicit recovery/readback then refreshes the UI. BLE SET is read from the same owner on the next UI slice.

Rendering uses the existing Scene and scene-owned full invalidation, with an actual one-row clipped target over 128 fixed RGB565 pixels. Each UI step performs at most one actual Display::write. The row cursor advances only after confirmed display success. Failure retains that row; a model, observation revision or calendar change starts damage when idle and coalesces one followup pass while a pass is active. Active row progress is preserved so continuous valid updates cannot starve lower rows; after updates stop, at most the current remaining rows plus one full pass converge to the latest scene. Observation generations must be nonzero and nondecreasing, and change whenever any observation changes. Calendar changes are tracked independently. No borrowed Scene or snapshot is retained across steps; there is no self-reference or framebuffer.

This preserves the existing V2 rendering, including its existing DEMO labels and format-preview sample text. The adapter injects real observations but does not claim final product branding. Synchronous store/display calls still need qualified platform latency or cooperative wait integration. Offline tests establish logical slice fairness and bounded render rows, not real-time BLE/radio/display/Flash timing.

## Offline evidence

Product tests use real AtomicSnapshot, selected codecs, all six real owner families, real settings/time service handlers, protocol Session/ControlConnection and Runtime. Only physical medium, normalized input, observation/calendar/action ports, display and transport queues are test fixtures. They cover touch→durable→wire GET, wire SET→UI, actual time wire GET/SET, reconstruction, failed/uncertain commit, separate authority and revocation, display damage retry, missing observations/actions/time, exact dictionaries, five CCCD generations with fresh HELLO sessions, extension lifecycle/replay/cleanup, duplicate/unbound route rejection and actual frame-ceiling negotiation. Six-owner recovery tests inject a read failure into every partition independently and preserve actual object reservations/body, history ACK, UTC evidence and retained Accepted job identity; the combined source profile additionally preserves nonempty HR policy/zones. No physical clear/reset effect is executed.

Actual board initialization, Flash write/partition policy, trustworthy boot/time provenance, product/GATT identity, radio transport, display/touch ports, observations/calendar, authorization and optional executors remain required platform bindings. Default self-check metadata remains unchanged and does not become hardware-qualified by enabling this library.

## Asynchronous shared settings

`SettingsFactory::new` is the additive settings-only CONTROL entry. It requires the actual ready `AsyncPropertyStore<CodecSchemas>` and independent live property policy, advertises only available core 00 and settings 04, and rejects any other available module. Its supplied logical maximum and module-04 input/output maximum are exactly 128; DATA is zero. The retained handler uses R=128 exact request bytes. Other modules may be omitted or declared unavailable with clear features and capacities. No time or observation provider is created by this factory. Existing synchronous ProductFactory remains unchanged.

Explicitly recover an `IncrementalSnapshot` before opening the owner. A confirmed blank owner needs complete caller-supplied `begin_initialize` defaults and actual terminal success before views are constructed. Corrupt, uncertain or unready owners do not take a default-initialization path. The selected complete three-field settings image fits N=128 in offline tests; callers must check their actual selected catalogue, dictionaries, medium and layout. There is no production RAM durable backend or physical Flash binding here.

Borrow the same owner for `AsyncSettings`, `SettingsFactory`, and `SettingsWork::new`. Supply `SettingsWork` as Runtime's independent background port; each step calls the owner once, even after its connection actor detaches. Each successful factory open returns one actual persistent `AsyncPropertyHandler`; readiness inspects a retained token rather than reconstructing handlers or driving storage. SET produces the existing final status/revision only after final sync and exact readback. Disconnect, CCCD revocation, timeout and authority revocation suppress delivery; accepted work continues under the boot owner. Attached terminal results remain reserved until consumed/detached. Explicit shutdown and removal of old actors/controllers precede owner recovery. New views must validate actual recovered state.

`AsyncProductUi::new` has the same supplied time/observation/calendar/display/action requirements as ProductUi and uses the same private event/render path. It does not make the full UI usable when mandatory observations/time are unavailable. A durable touch save retains its candidate separately; confirmed appearance and editor navigation remain visible while pending. The UI consumes at most one normalized event per pending slice and ignores its effects, including navigation/actions. It checks save authority before any missing-time/observation early return, and rechecks it immediately before navigation publication after callbacks. Terminal success reloads the shared confirmed appearance and publishes the saved navigation once; failure discards the candidate and retains the editor. Accepted storage remains independent of UI Drop or scope loss. Ordinary BLE pending values remain invisible; completed BLE changes load on the next valid UI slice.

For direct local use, `AsyncSettings::begin` accepts a save without doing medium I/O, `poll` inspects actual owner completion without advancing it, and `finish` releases successful local publication state after readback. Early finish fails. `detach`/Drop suppress local delivery without cancelling accepted work. Local contention maps existing PropertyFailure::Busy to PortError::Fault because the port enum has no Busy variant; BLE retains its existing Busy wire status. Face/theme/text size keep the existing explicit RamOnly/Unavailable policy.

Offline async tests use staged physical-medium models with actual `IncrementalSnapshot`, owner, codecs, Session/ControlConnection, Runtime, and the pinned Host/ATT/GATT transport. They prove pending touch navigation, confirmed reads, mutual UI/BLE exclusion, final sync/readback failures, revocation/Drop continuation, duplicate replay, and CCCD teardown/re-enable followed by durable reconstruction. These are software integration results. No change activates native storage binding or establishes physical timing, durability, aggregate RAM/stack fit, or hardware availability.
