# 公共接口的完成、所有权和恢复契约

本页补充现有 trait 的使用约定，不改变其方法、错误枚举、默认功能或对象布局。

| 接口 | 成功表示 | 调用方仍负责 |
| --- | --- | --- |
| Display::write | 逻辑写及其同步传输完成，输入像素可复用 | 屏幕实际可见刷新、电子纸 present、复位后 generation/rebind |
| SpiWrite/DisplayBus | 实际同步传输完成，返回后不再访问输入 | 每个操作和清理的有限等待、CS、电气时序 |
| ReadAt | 指定范围精确读完，返回后不再访问输出 | 真实容量、读取上限、本帧内容稳定；错误时丢弃整段输出 |
| BLE QueueAccepted | 后端已接受或复制完整输入，输入可复用 | 空口完成、对端 ACK、连接代次、CCCD、bearer 和竞态复核 |
| input sample/update | 本次状态和最多一个事件已提交 | 保留失败样本、先重试再推进输入流；跨 ISR/task 同步 |

## 错误与恢复

- 确定未提交的容量错误／队满可以由适配器明确报告为背压。任意后端错误不等于
  “没有副作用”，不能自动重发；结果不确定时先按后端契约查询、清理或恢复。
- 保留原始后端错误供调用方判断。错误编号是应用诊断的映射，不以 Rust 枚举顺序
  或 Debug 文本作为长期协议编号；不要求所有组件依赖统一诊断中心。
- SharedBus 限同一前台所有者，不能用于 ISR 并发；所有设备使用同一已配置模式和频率。
  发生错误会锁存故障，取回资源不等于已完成硬件恢复。
- 异步 DMA 适配若实现当前同步接口，必须等到传输完成再返回。未来异步接口应单独
  定义借用、完成和取消语义，不得悄悄改变旧接口。
- UI 的 service 回调只是成功刷新块之间的合作执行点。Idle、节流或失败时可能不调用，
  因此应用必须独立驱动 BLE 和其他服务；逻辑块预算不是实时截止时间保证。

## 时间与资源

input 使用同一启动代次内的单调微秒；UI frame-pacing 也使用微秒。产品协议若使用
毫秒必须显式换算。UTC、硬件低位计数器扩展和新启动代次由适配器管理；不同模块可以
采用不同的时钟回退策略，不能只因底层都是 u64 就混用。

UI 的 ResourceKey/Metadata/View 仍只有一套。稳定目录可借用不可变 descriptor，
读者和传输 scratch 则由绘图闭包独立可变借用；见 assets 的实际组合测试。
版本变化由调用方明确提交到 UI。只读窗口只约束地址，不提供内容快照、写入事务或
掉电原子性。未来写入引擎必须另行声明介质的擦写／同步／掉电模型。

## 调试输出

WriteSlot、SliceSource、ReadRef、ReadWindow 和输入 EventQueue 仅输出元信息；不展开
当前或旧载荷、路由目标及底层 provider。实现 Debug 不要求 backend 自身实现 Debug。
clear/take/pop 是逻辑删除，不提供安全擦除。公开错误仍保留原始 E，应用记录错误前
应自行映射或审查其 Debug，不能把未知 SDK 错误内容自动发到日志。

## 兼容和裁剪

新模块由应用选择依赖，现有 core/UI 不反向依赖 assets/input/storage/BLE。
Cargo feature 会合并；库 feature 不用于相互排斥的 RAM 档位。调用方的实际数组和
const 容量决定缓冲占用。保留旧接口消费者、无／默认／全功能及功能合并检查。
离线链接、局部栈帧和对象大小不等于完整固件峰值或任何新平台的硬件验证。
