### R1：编译拒绝的原因判定存在误报（P2，已关闭）

原 `scripts/check_ui_configuration.py` 将 stdout/stderr 合并，仅搜索关键词。
开启 layout 后成功导入 LayoutSettings，再故意调用一个不存在的无关函数：
编译器仅报 E0425，无用导入 warning 却包含 LayoutSettings，旧门禁仍返回通过。
这是测试证据可靠性缺陷；没有据此发现当前实际接口裁剪失效。

修复：

- Cargo 采用 JSON 诊断；只匹配真正的 error，不从 warning、渲染文本或源码片段取证。
- 校验消费者来源、错误码、错误自身描述；通常还校验 primary span 位于该消费者。
  相对位置按其 Cargo.toml 目录解析；RUN 常量错误允许来自库内断言，但仍须归属于
  该消费者编译，并匹配 E0080 和明确的 RUN 断言消息。
- 出现任何不匹配的附加错误都拒绝。编译器崩溃、缺工具、非零退出但无预期诊断，
  也不能冒充通过。
- 新增10项维护中的 Python 回归，覆盖 warning 误报、混合错误、来源和 primary
  span 归属、相对路径、无结构化错误、成功状态和 JSON 破损等。

先复现旧门禁误绿，再观察新测试失败，修复后通过。真消费者另证实：合法使用成功，
实际缺失 API 按 E0432 拒绝，原 warning＋E0425 反例及 E0432＋E0425 混合反例
均被门禁拒绝。原审查角色独立复验修复，没有发现新增问题。

## 本轮新增的独立验收证据

- 配置／资源角色：6项独立运行用例，另有3项编译拒绝。覆盖无 Default／编码转换
  的自定义颜色、失败 update/rebind 的 settings/policy/dirty/binding/anchors
  原子性、同一资源地址的新 revision、元数据表示边界、借用约束、读取故障与节流
  恢复。实际消费 padding/gap/角色配色和显式覆盖，tile=1/2/4/9 图像一致。
- 刷新角色：9项独立运行用例。其中一项包含201个逐 tile 故障组合，跨 Dirty 和
  FullOnRequest、4种分块容量，逐一覆盖 scene/write/service 失败、完整请求保留、
  首末 future 请求合并和完整重试。201是参数组合数，不是201个新测试函数。
- 几何／时间边界：分别完成65535×1和1×65535整帧、65535×65535右下角单像素、
  零尺寸拒绝与恢复、最大 u32 间隔、u64 回绕、missing clock、锚点启停与回退。
  没有执行超过40亿像素的完整65535×65535整帧。
- 裁剪角色：16组请求子集测试、30个真实消费者、七组 ARM 布局及链接段独立重建，
  与开发记录一致。13个实际拒绝消费者在旧门禁复核中也均报正确错误；修复后重新
  用结构化诊断跑完整矩阵，仍全部通过。

这些独立复验保留于本地忽略目录 `target/ui-config-review-r02/`，没有全部移入维护
测试套件；其结果不累加到 workspace 的独立测试数量。维护套件新增的是门禁回归。
